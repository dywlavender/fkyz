# Rule Engine v4

标准正文中的规则必须是已选定、可执行、可验证的确定口径，不是歧义清单。

## Rule Level

所有进入标准正文的业务规则统一使用：

| Level | 含义 |
|---|---|
| hard | 已选定、可执行、必须遵守并可验证的标准口径 |

不得把 `unclear`、`suggestion` 或“待确认后再定”写成主链规则。

## Basis Type

| basis_type | 含义 |
|---|---|
| requirement | 需求直接明确 |
| api_doc | 接口文档直接明确 |
| public_rule | 公共业务规则直接明确 |
| deterministic_inference | 可由输入唯一推导 |
| selected_interpretation | 存在多种实现时已选择的最可能口径 |

## Rule JSON Contract

每条规则必须包含：

- `rule_id`
- `dimension_ref`
- `source_section`
- `standard_level`，固定为 `hard`
- `basis_type`
- `basis_text`
- `evidence_ids`
- `selection_reason`，非选定解释时为空字符串
- `content`

`basis_type = selected_interpretation` 时，必须引用 `SEL-xxx` 并提供非空 `selection_reason`。

# Evidence Engine v4

Evidence ID 按来源类型固定：

| Evidence 前缀 | 来源类型 |
|---|---|
| REQ | 需求内容 |
| API | 接口文档 |
| PUB | 公共业务知识规则 |
| INF | 确定性推导 |
| SEL | 选定解释 |

排序规则：REQ、API、PUB、INF、SEL，同类型按原文或选择顺序编号。

每条 hard 规则必须引用至少一个 Evidence ID。

使用 `SEL-xxx` 时，必须在「选定解释」章节写明原始歧义、选定口径和选择理由。选择理由应说明为什么该方案最贴近需求语义和可用接口字段，不能只写“根据经验”。

# Freeze Rule

本阶段已冻结的输入、证据和规则集合不得在最终输出时临时扩充或改写。阶段专用冻结对象以本阶段规则为准。

---

# Deterministic Output v4

相同输入必须输出相同章节、相同对象顺序和相同判定口径。具体章节、编号和对象顺序以本阶段专用规则为准。

---

# Review Contract v4

本阶段只依据已冻结的结构化标准和待评审内容执行差异判定，不得重新生成或改写标准。

## 冻结对象

| 冻结对象 | 处理状态 | 冻结后限制 |
|---|---|---|
| STRUCTURED_STANDARD_JSON | STATE2 | 不得改写标准 JSON |
| REVIEWABLE_RULE_SET | STATE3 | 不得新增可评审规则 |
| DRAFT_PARSE_SET | STATE4 | 不得重新解释待评审输入 |
| ISSUE_SET | STATE5 | 不得新增未判定问题 |

冻结后如发现需要新增标准规则或重新解释待评审输入，不得直接新增问题；只能依据当前冻结对象完成判定。

## 章节顺序

1. `# 评审报告`
2. `## 输入解析`
3. `## 总体结论`
4. `## 汇总问题清单`
5. `## 待确认项`

不得基于防幻觉规则新增评审标准；防幻觉规则只用于阻止生成没有冻结标准依据的问题。

# Phase 2 Issue Guard

Phase 2 使用封闭世界差异判定：结构化标准 JSON 中冻结的 v4 hard 规则是唯一可评审规则集。待评审准出内容出现标准未规定的描述，不自动构成不符合；“标准未规定”不等于“标准禁止”。

## 问题准入类型

候选问题必须属于以下一种确定差异：

1. `missing_required_semantics`：待评审准出内容缺少某条 hard 规则要求、且会影响标准算法唯一还原的必要语义。
2. `direct_contradiction`：待评审准出内容与某条 hard 规则的字段、条件、边界、聚合、计算或异常兜底结论直接矛盾。
3. `result_changing_addition`：待评审准出内容增加了额外操作或分支，并且能够确定该操作或分支会改变标准算法的取值、过滤范围、聚合对象、异常行为或最终结果。

不属于以上任一类型的差异不得进入问题清单。

## 问题准入四要素

每个候选问题在进入最终报告前必须同时具备：

1. **标准依据**：引用结构化标准 JSON 中存在的 hard `rule_id`，并准确复述该规则的 `content`。
2. **准出差异**：指出待评审准出内容中的具体缺失、矛盾表述或结果变化操作，不得只概括为“与标准不一致”。
3. **冲突类型**：明确归入 `missing_required_semantics`、`direct_contradiction` 或 `result_changing_addition`。
4. **确定性影响**：说明差异通过什么逻辑链改变哪个取值、范围、边界、聚合对象、异常行为或最终结果；不得只声称存在改变的可能性。

任一要素缺失，必须丢弃该候选问题，不得降级为待确认或建议。

## 标准解释继承

当待评审准出内容沿用需求中的同一业务运算表达，且涉及的字段、运算方向、偏移量、比较符和包含边界与标准一致时，视为继承结构化标准对该表达的 `selected_interpretation`。

- 准出内容不需要再次逐项复述标准对同一表达的格式对齐、自然月计算或月末回退等展开细节。
- 只有准出内容缺少该业务运算本身，或者明确采用不同字段、不同偏移量、不同粒度、不同公式或不同边界时，才能进入问题清单。
- 不能仅以“无法从准出逐字还原标准展开过程”为由认定 `missing_required_semantics`；必须证明准出允许的另一种解释会在其明确表述范围内改变结果。

## 根因归并

最终问题清单按能够直接指导一次修改的根因归并：

1. 加工对象或数组路径错误时，优先输出一条加工对象错误，不再分别输出该错误对象下每个叶子字段缺失。
2. 同一字段映射错误在 D1、D2、D4、D5 中产生的派生差异，应合并为一条字段或对象根因问题，并可同时引用相关规则。
3. 同一根因同时满足 `direct_contradiction` 和 `missing_required_semantics` 时，优先保留 `direct_contradiction`。
4. 只有修改动作和结果影响相互独立时，才能拆分为多条问题。

执行归并时必须先形成“字段/对象映射、过滤条件、取记录方式、计算公式、异常兜底”五类根因槽位，再生成最终问题：

- D1 字段缺失与 D2 对同一批字段的溯源错误只能占用一个“字段/对象映射”槽位。
- D4 的取第一条/取最大值差异与 D5 对同一取记录动作的重复描述只能占用一个“取记录方式”槽位。
- 一条问题可以同时引用多个 dimension_ref 和 rule_id；不得为了逐维度覆盖而拆成重复问题。
- 如果两条候选问题具有相同的字段集合、相同的错误表达或相同的修改建议，必须合并。

## 标准沉默与中性描述

以下理由不能单独支持 `❌ 不符合`：

- “标准未规定”
- “超出冻结标准范围”
- “可能改变结果”
- “可能影响实现验收”
- “准出内容增加了标准中没有的文字”

待评审准出内容中的补充描述，如果没有引入实际转换、过滤、舍入、换算、分支或其他结果变化操作，应视为中性描述。例如：

- 标准只规定对原始金额求和，准出内容写“保留原始精度”，但未规定新的保留位数或舍入动作：中性描述，不构成问题。
- 金额字段和标准结果单位均为元，准出内容补充“结果单位为元”，但没有乘除换算：中性描述，不构成问题。
- 准出内容说明使用某个变量名、数据类型、比较工具或代码组织方式，且不改变业务结果：实现细节，不构成问题。
- 准出内容已经表达“字段缺失、格式错误或数据异常时返回默认值”等统一异常兜底语义时，其在任意章节出现的 `0`、`-1`、`null`、空字符串等具体默认值只视为当前配置值示例，不比较、不输出问题，也不得推测配置值可能不同。

如果补充描述包含确定的结果变化操作，则按现有 hard 规则判断。例如：

- 标准结果为筛选记录的金额总和，准出内容规定求和后四舍五入保留两位小数：属于 `result_changing_addition`，因为舍入会使部分有效输入下的最终结果不再等于标准求和结果。
- 标准结果为金额总和，准出内容规定求和后乘以 100：属于 `direct_contradiction` 或 `result_changing_addition`，因为最终结果被确定性改变。

Phase 2 不得引用本 Guard 自身作为业务问题依据；本 Guard 只决定候选问题能否进入问题清单。

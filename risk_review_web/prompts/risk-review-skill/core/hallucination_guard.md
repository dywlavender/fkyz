# Hallucination Guard

以下内容如果没有来自本阶段允许使用的输入或规则材料的明确依据，一律不得新增：

1. 新字段
2. 新接口
3. 新接口调用步骤
4. 新过滤条件
5. 新状态码
6. 新成功码
7. 新枚举值
8. 新默认值
9. 新兜底分支
10. 新时间窗口
11. 新边界条件
12. 新单位换算
13. 新精度
14. 新四舍五入方式
15. 新排序规则
16. 新去重规则
17. 新取最新/取第一条规则
18. 新分组字段
19. 新条件分支
20. 新业务规则
21. 新 Java 实现约束
22. 不改变字段值或加工结果的重复解析、同格式转换、同粒度转换

处理规则：

- 有明确依据：写入对应规则，并引用 Evidence ID。
- 完全没有输入依据的内容：不得新增。
- 只是工程实现建议且不影响加工结果：不写入标准。
- 无业务效果的操作，即使技术上可以执行，也不得包装成 hard 规则、确定性推导或选定解释。
- 仅格式名称、符号或书写方式不同，但数据组成、排列顺序和粒度相同，不构成格式转换依据；不得使用“规范化”等模糊措辞制造实际不存在的转换。

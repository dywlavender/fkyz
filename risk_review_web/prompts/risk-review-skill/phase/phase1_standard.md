# 标准加工规范生成 Skill v5

## 1. 目标

根据需求内容、指定接口文档、公共业务规则和隔离目录中的《因子加工开发规范》，生成唯一、最可能、可直接执行的标准加工规范。

标准加工规范本质是一份标准答案版的加工逻辑，不是证据审计报告、接口说明书、歧义清单或工程实现方案。

不得读取待评审加工逻辑，不得输出评审报告。

## 2. 输入与读取范围

必须读取：

- 本 Skill；
- `risk_review_web/prompts/risk-review-skill/spec/factor_processing_spec.json`；
- 输入指定的接口文档；
- `risk_review_web/data/business_rules.json`。

必须使用同一份开发规范，不得在 Skill 中另建或扩写一套通用规则。

接口字段均视为加工阶段已经取得并可直接读取，不讨论接口调用方向、请求步骤或技术实现。

## 3. 生成原则

1. 严格遵循开发规范中的 `SOURCE-001`：保留输入已有约束，只补足执行所必需且会导致不同结果的信息，不得为了形式完整扩张业务语义。
2. 需求已经可以直接执行时，不得继续补充终点、边界、精度、单位、排序、去重、状态、空集合返回值或其他“更完整”口径。
3. 需求仅有单边时间条件时，只生成该单边条件；不得强制补成双边窗口。
4. 需求明确给出偏移量和比较符时原样保留，不得为了凑成自然月数量改变公式。
5. 时间字段粒度不同且会改变比较结果时，写明必要转换；相同格式、相同粒度或不改变结果的转换不写。
6. 需求中的业务概念必须映射到指定接口的真实叶子字段。只有存在唯一或最可能映射时才选择；完全无法映射时只输出 `缺少要素：【接口字段：业务概念】`。
7. 原始材料存在多种会产生不同结果的合理实现时，选择最可能的一种作为标准逻辑，不输出多套候选方案。
8. 不输出不适用章节或不适用加工步骤。

## 4. 因子加工输入字段

只列实际参与取值、转换、过滤、时间窗口、计算、聚合、关联或条件分支的叶子字段。

- 完整路径必须从接口名称开始，由“接口名称 + 接口内字段层级”组成，固定写为 `接口名称.接口内字段路径`，并用反引号包裹。
- 不得只写字段简称或接口内相对路径。即使接口文档字段表只展示相对路径，也必须在输出时补上该接口文档的名称。
- 纯数组、列表、对象容器不单列，通过叶子字段完整路径表达层级。
- 字段清单和加工步骤使用同一字段路径。
- 字段用途使用简洁业务描述，不重复字段类型、格式、接口方向或中文释义。

## 5. 标准加工逻辑

按可执行顺序输出步骤。逻辑类型只能使用开发规范 `logic_types` 中的封闭枚举：

- `time_filter`
- `condition_filter`
- `iteration`
- `aggregation`
- `derivation`
- `branch`

只输出实际存在的步骤。标准逻辑必须明确会影响结果的字段、条件、比较关系、偏移、必要粒度转换、遍历范围、聚合对象、公式和分支。

请以资深风控因子开发人员的标准编写加工逻辑。加工逻辑应专业、清晰、可直接实现，开发人员无需再次推测即可唯一还原加工结果。

### 专业加工逻辑编写规范

1. 按数据实际流转顺序说明必要转换、遍历、筛选、计算和聚合，前后步骤应形成连续加工链路。只有取值范围、取值条件或取值优先级会改变加工结果时，才单独描述字段取值规则；输入字段声明及业务概念与接口字段的对应关系不作为加工步骤。
2. 每个步骤应明确操作字段、明细集合或前一步结果，不得使用无法定位处理对象的概括描述。
3. 会影响结果的字段、条件、偏移、比较关系、边界、运算顺序和分支必须能够唯一还原；不得新增输入材料中不存在的业务口径。
4. 时间偏移、比率、差值及其他数值运算可以使用必要数学公式；取值、遍历、筛选和聚合使用专业自然语言，不强行拆分或过度公式化。
5. 只描述业务加工规则，不指定编程语言、函数、SQL、框架或不会影响加工结果的实现细节。

因子加工开发规范用于保证各类加工操作的业务正确性，不得逐条翻译规范或为了覆盖规则机械拆分步骤。


## 6. 默认值兜底

固定表达：

> 因子加工输入字段缺失、格式错误或数据异常导致无法完成正常加工时，返回配置的默认值。

不写具体默认值。只有输入材料明确规定且会改变结果的单条明细异常、空集合或特殊运算处理，才写入对应加工步骤。

## 7. 输出契约

必须严格输出以下三个二级章节，不能增加其他二级章节：

1. `## 因子加工输入字段`
2. `## 标准加工逻辑`
3. `## 默认值兜底`

字段表固定为：

| 字段完整路径 | 加工用途 |
|---|---|

加工逻辑表固定为：

| 步骤 | 逻辑类型 | 标准逻辑 |
|---|---|---|

首行必须为 `# 标准加工规范`。只向 stdout 输出完整 Markdown 正文，不得输出 frontmatter、checksum、文件路径、计划、检查过程或代码围栏，不得自行保存文件。

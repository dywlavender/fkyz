# 风控因子标准加工规范生成 Skill v4

## 1. 目标

根据需求内容、指定接口文档和公共业务知识规则，生成一套唯一可执行的标准加工逻辑。

本阶段不是整理歧义、列举候选方案或等待业务确认。原始材料存在多种合理实现时，必须选择最可能的一种，写入 `## 选定解释`，并将选定结果作为 `hard` 标准供 Phase 2 严格评审。

不得读取待评审准出内容，不得输出评审报告。

## 2. 输入与读取范围

必填输入：

- 需求内容
- 至少一个接口文档名称

接口文档只能从项目接口文档目录中按输入名称匹配并读取。公共业务知识规则从 `risk_review_web/data/business_rules.json` 读取。不得读取 Phase 2 准出内容来反推标准。

接口字段均视为加工阶段已获得并可以直接读取，不讨论请求/响应方向，也不补充接口调用步骤。

## 3. 唯一标准生成原则

### 3.1 主链必须全部确定

以下内容只允许输出 `hard`：

- D1 因子加工输入字段
- D2 字段溯源
- D3 过滤条件、时间粒度、格式转换、窗口起止和包含边界
- D4 数组遍历、筛选对象、聚合对象和空数组语义
- D5 取值、转换、过滤、聚合、计算步骤
- D6 异常返回配置默认值的兜底语义
- D8 比率或衍生计算
- D9 条件分支

禁止在这些章节输出“未明确”“待确认”“疑问”“建议口径”“无法确定”或多套候选方案。

### 3.2 依据与选定解释分离

规则必须使用下列依据类型之一：

- `requirement`：需求直接明确，引用 REQ。
- `api_doc`：接口直接明确，引用 API。
- `public_rule`：公共规则直接明确，引用 PUB。
- `deterministic_inference`：可唯一推导，引用 INF，并写明推导链。
- `selected_interpretation`：存在多个实现，选择最可能方案，引用 SEL，并在「选定解释」登记理由。

`selected_interpretation` 仍是 hard。它表示“这是本次准出评审采用的标准答案”，不表示原始材料逐字明确。

### 3.3 最可能方案选择顺序

发生歧义时按以下顺序选择，不能停止：

1. 优先采用需求明确写出的字段、运算、边界和分支。
2. 需求字段在接口中不存在时，在已指定接口内选择业务含义最接近、类型和粒度最匹配的唯一字段。
3. 两个字段粒度不同但必须比较时，将基准时间转换为加工字段的粒度；转换规则必须写清。
4. 需求明确给出 `基准时间-N个月`、`>=`、`<=` 时，保留该算式和包含边界，不因字段映射歧义而丢失。
5. 仅写“近 N 个月”而未给公式时，默认以基准月份为终点、向前取包含终点在内的 N 个自然月，并登记 SEL。
6. 金额类明细因子在需求要求得到期间金额、且存在唯一金额字段时，默认遍历符合条件记录并 SUM；若需求明确 AVG、MAX、MIN、COUNT 等则以需求为准。由语义选择 SUM 时登记 SEL。
7. 不得选择输入中不存在的字段、状态码、枚举、过滤条件、分组、去重、排序或单位换算。

### 3.4 因子加工输入字段

只列直接参与取值、转换、过滤、时间窗口、计算、聚合、分组或分支的叶子字段。

- 数组、列表、对象容器不作为 D1 独立字段。
- 容器层级通过 `content[].field` 等完整叶子路径表达。
- 只有直接计算数组长度、存在性或数量时，容器本身才可进入 D1。
- 仅用于接口查询、参数传递、主体关联或上游取数的字段不得进入 D1。

### 3.5 默认值

具体默认值是 0、null、空字符串还是其他值，不属于 Phase 1 标准，也不作为 Phase 2 差异依据。

D6 只生成一条 hard 语义：

> 因子加工输入字段缺失、格式错误或数据异常导致无法完成正常加工时，返回配置的默认值。

不得在 Phase 1 写具体默认值，不得要求 Phase 2 比较具体默认值。正常无符合记录是否走默认值，应结合聚合语义在 D4/D5 中确定；异常兜底统一引用 D6。

## 4. 时间窗口完整性

只要涉及时间窗口，D3 必须同时明确：

1. 过滤字段完整路径
2. 基准时间字段
3. 时间窗口粒度
4. 必要格式转换
5. 窗口起点公式
6. 窗口终点公式
7. 起点是否包含
8. 终点是否包含

自然语言“近 N 个月内”不能替代以上结构。

## 5. 证据编号

- REQ-001 起：需求原文
- API-001 起：接口字段或结构
- PUB-001 起：公共规则
- INF-001 起：唯一推导
- SEL-001 起：选定解释

每条规则必须至少引用一个 Evidence ID。SEL 必须能在「选定解释」表中定位。

## 6. 输出结构

必须严格按以下顺序输出，不能增加其他章节：

1. `# 标准加工规范`
2. `## 输入解析`
3. `## 因子加工输入字段`
4. `## 字段溯源`
5. `## 过滤条件`
6. `## 列表/数组字段处理`
7. `## 计算逻辑`
8. `## 默认值兜底策略`
9. `## 比率/衍生因子计算`
10. `## 条件分支逻辑`
11. `## 选定解释`

所有规则表的依据等级统一写 `hard`。

## 7. v4 结构化标准契约

Python 后端抽取的 JSON 使用 `risk_review_standard_json_v4`，顶层必须包含：

- `schema_version`
- `inputs`
- `field_lineage`
- `filters`
- `array_handling`
- `calculation`
- `default_strategy`
- `ratio_or_derivation`
- `conditional_branches`
- `selected_interpretations`
- `source_metadata`
- `rules`

每条规则的 `standard_level` 固定为 `hard`。`basis_type = selected_interpretation` 时必须提供 `selection_reason`。

## 8. 输出与保存

只向 stdout 输出完整 Markdown，首行必须为 `# 标准加工规范`。不得保存文件，不得输出 frontmatter、checksum、计划、检查过程、摘要、文件路径或代码围栏。

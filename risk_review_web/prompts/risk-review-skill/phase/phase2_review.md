# 风控因子准出内容评审 Skill v4

## 1. 目标

只使用【结构化标准 JSON】中的 v4 hard 规则，对【待评审准出内容】执行严格对比并输出评审报告。

Phase 2 不重新读取接口文档、不重新推导标准、不修改选定解释，也不因为自己认为另一种实现更合理而放宽或改写标准。

## 2. 输入要求与版本门禁

必须提供：

- 可解析的结构化标准 JSON
- 待评审准出内容
- 明确的校验模式

无论严格模式还是跳过模式，`schema_version` 必须等于 `risk_review_standard_json_v4`。旧版本不兼容，必须重新执行 Phase 1。

### 严格模式

输入明确写明“校验模式：严格；已由外部程序校验通过”时继续。checksum 或 v4 schema 校验失败时停止，由后端返回错误。

### 跳过模式

输入明确写明“校验模式：跳过；已按运行开关跳过”时，允许跳过 checksum 和完整语义校验继续评审，不得输出 checksum 停止提示。

跳过模式只跳过校验过程，不兼容旧 schema，也不改变任何 hard 规则的约束力。

## 3. 规则使用边界

1. v4 `rules` 中每条业务规则都必须是 `standard_level = hard`。
2. `basis_type = selected_interpretation` 与 requirement、api_doc、public_rule、deterministic_inference 具有相同评审效力。
3. Phase 2 不得把“选定解释”降级为建议或待确认。
4. 只能引用 JSON 中存在的 rule_id、dimension_ref、content 和 evidence_ids。
5. JSON 缺少可定位规则时不得自行补全；严格模式由后端阻断，跳过模式只评审仍可定位的 v4 hard 规则。

## 4. 固定评审顺序

### 4.1 因子加工输入字段

按 D1 检查：

- hard 叶子字段是否全部声明
- 字段名大小写是否逐字符一致
- 同名字段无法唯一定位时，完整接口和对象/数组路径是否齐全
- 不要求把纯数组、列表、对象容器单独列为加工输入字段
- 标准要求直接计算容器长度、数量或存在性时例外

不得要求补充仅用于接口查询、参数传递、主体关联或上游取数的字段。

### 4.2 字段溯源

按 D2 检查准出文档实际使用的字段是否与标准选定字段一致。`selected_interpretation` 选择的字段映射必须严格执行。

### 4.3 过滤和时间窗口

按 D3 逐项检查：

- 过滤字段
- 时间粒度
- 格式转换
- 基准时间
- 起点公式
- 终点公式
- 起点包含关系
- 终点包含关系
- 多条件 AND/OR

“近 N 个月内”“按最近一段时间”等高层描述，不能替代标准中的明确字段、转换、公式和边界。只要无法从准出文档唯一还原标准算法，即判 `❌ 不符合`。

### 4.4 列表/数组处理

按 D4 检查遍历对象、遍历范围、过滤顺序、聚合对象和空数组/无符合记录处理是否一致。准出文档描述“筛选记录后求和”可以表达遍历，但不得遗漏会改变结果的嵌套数组、关联或保留逻辑。

### 4.5 计算逻辑

按 D5 检查取值、格式转换、过滤、SUM/COUNT/AVG/MAX/MIN、单位换算、分组和结果计算。标准选定 SUM 时，其他聚合或未写聚合方式均判不符合。

### 4.6 默认值兜底

D6 只评审异常兜底语义：

> 因子加工输入字段缺失、格式错误或数据异常导致无法完成正常加工时，返回配置的默认值。

不比较默认值具体是 0、null、空字符串或其他值；不得因为具体默认值不同输出问题。

如果准出文档只写一个具体值，但没有表达异常时返回默认值，视为兜底语义缺失。

### 4.7 比率和条件分支

按 D8、D9 检查分子、分母、零分母处理、公式和条件分支。标准写明不适用时，准出文档不得引入会改变计算结果的额外衍生或分支。

## 5. 问题判定

满足以下任一条件，输出 `❌ 不符合`：

- 缺少 hard 加工字段
- 字段名或字段路径不一致
- 与 hard 选定字段映射不一致
- 时间窗口字段、粒度、转换、起止公式或边界缺失/不一致
- 遍历、过滤、聚合或计算方式缺失/不一致
- 条件分支缺失/不一致
- 未表达异常返回默认值的兜底语义

只影响具体默认值、变量名、代码组织、日志或实现工具类，且不改变最终数值的差异不得输出问题。

`🔵 待确认` 只用于 v4 JSON 本身缺少可验证规则、公共规则快照不一致等无法归责于准出文档的输入异常。不得用它放行准出文档与 hard 标准的差异。

## 6. 总体结论

- 存在任一 `❌ 不符合`：`❌ 不通过，需修改`
- 无不符合但存在输入异常待确认：`🔵 待确认`
- 无不符合、无待确认：`✅ 通过`

## 7. 输出结构

只能输出以下章节，不能增加“逐项检查说明”、检查回执、自检明细、加工字段完整性详情或运行过程：

1. `# 评审报告`
2. `## 输入解析`
3. `## 总体结论`
4. `## 汇总问题清单`
5. `## 待确认项`

### 0. 输入解析

| 项目 | 内容 |
|---|---|
| 标准规范来源 | 已提供标准规范 |
| 标准规范校验 | 严格模式写“已由外部程序校验通过”；跳过模式写“已按运行开关跳过” |
| 结构化标准 JSON | 已提供，schema 为 risk_review_standard_json_v4 |
| 公共业务知识规则 | 已提供 / 无 |
| 待评审准出内容 | 已提供 |

### 总体结论

| 项目 | 内容 |
|---|---|
| 总体结论 | ✅ 通过 / 🔵 待确认 / ❌ 不通过，需修改 |
| 问题统计 | ❌ 不符合 N 项 / 🔵 待确认 N 项 / ⚠️ 建议 N 项 |

### 汇总问题清单

| 序号 | 维度 | 级别 | 核心问题 | 依据 | 影响 | 修改建议 |
|---|---|---|---|---|---|---|

问题编号：字段完整性使用 I-001 起，逻辑一致性使用 L-001 起。

「依据」必须包含 rule_id、dimension_ref、source_section、standard_level、basis_type 和标准结论；选定解释还应包含 selection_reason 摘要。

没有问题时保留表头并写一行 `| 无 |`，之后直接进入「待确认项」，不得输出内部检查过程。

### 待确认项

没有输入异常时写「无」。

## 8. 禁止行为

- 不得重新推导或改写标准
- 不得读取接口文档补充规则
- 不得把选定解释降级
- 不得比较具体默认值
- 不得输出标准规范正文
- 不得保存文件或编造 checksum
- 不得输出摘要、计划、检查明细或代码围栏
